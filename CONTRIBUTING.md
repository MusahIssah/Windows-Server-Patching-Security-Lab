# Updating this lab

Each phase adds evidence to the same repository.

1. Record the baseline, target, scope, and expected impact.
2. Make the controlled change and retain failures as part of its history.
3. Verify local results, service health, and centralized reporting separately.
4. Add selected screenshots using descriptive filenames.
5. Update the change register, milestone report, and roadmap.
6. Commit with a concrete description of the demonstrated result.

Use LAB-CHG identifiers for changes and label planned work explicitly. Historical snapshots describe the state when captured; later records may supersede them. Do not infer exact installation times from midnight `InstalledOn` values. Some screenshots and APIs show different timezone contexts.

Before publication, review newly added evidence for credentials or unrelated personal information. Keep raw logs and VM images in the local evidence archive unless they have been separately reviewed for release.

Example future commit subjects:

- `Document credentialed vulnerability scan baseline`
- `Verify remediation of selected scan findings`
- `Add tested firewall-log collection and alert evidence`

These examples describe future work, not results already achieved.
